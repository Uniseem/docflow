# 2026-09-25 Windows 去掉菜单栏

## 会话 1（Claude Code / Opus 5.5，Windows 机器，4.0.0 发布之后）

### 目标

维护者要求去掉 Windows 窗口里的「文件 编辑 窗口 帮助」菜单栏；确认过只去菜单栏，保留系统标题栏（不改成 macOS 那样的无边框顶栏）。

### 做了什么

- `src/main/app/menu.ts`：`buildMenuTemplate(platform)` 在非 macOS 上返回 `null`，删掉 Windows 分支（`退出`、没有「前置全部窗口」的窗口菜单）。
- `src/main/app/install-menu.ts`：模板为 `null` 时 `Menu.setApplicationMenu(null)`。必须显式设 `null`，不设的话 Electron 会装它自带的英文默认菜单。
- 菜单命令在界面里都有入口：检查更新、源代码、打开日志文件夹在「设置」里；`Ctrl+N` / `Ctrl+,` / `Ctrl+F` 本来就由渲染进程 `App.tsx` 处理；Windows 上输入框的复制粘贴由 Chromium 自己处理，不依赖菜单 role。
- 规划 02 §2.5 第 8 步、05 `app:command`、06 顶栏说明同步改写。

### 怎么验证的

- `npm run check`：通过，299 个单测（新增 `menu.test.ts`「Windows and Linux have no menu bar」）。
- `npm run dist:dir` 后用 Playwright 隐藏窗口启动 `release/win-unpacked/DocFlow.exe`：`Menu.getApplicationMenu()` 为 `null`，`isMenuBarVisible()` 为 false，标题 `DocFlow`。
- `npm run test:e2e`（隐藏窗口）：8 passed。

### 没做成 / 坑

- 没有肉眼看可见窗口（按之前的约定自动化不弹窗）；以上是程序化检查。

### 下一步

- 这个改动还没发版，已发布的 4.0.0 仍有菜单栏；要发 4.0.1 时按 07.5 改版本号、打标签。
