# 2026-09-25 发布 4.0.0

## 会话 1（Claude Code / Opus 5.5，Windows 机器）

### 目标

维护者决定不再做剩余任务（M5-8、M6-2、M6-3、M7-1～M7-4），直接发布 `v4.0.0`：Windows 提供安装程序（NSIS setup），macOS 用终端一行命令安装 `.pkg`。

### 做了什么

- 本地 `main` 落后 `origin/main` 4 个提交（M7-5 对齐与两轮修复），快进同步；`package.json`/`package-lock.json` 没变，不用重新安装依赖。
- `CHANGELOG.md`：Unreleased 定版为 `[4.0.0] - 2026-09-25`，加一句版本概述与比较链接。
- `docs/plan/09-milestones.md` 开头注明维护者的决定；未做的任务保持未勾选，留作 4.0.x 待办。
- `docs/plan/07-build-ci-release.md`：7.5 第 4 步注明没有打 beta 标签、改为在 `main` 上手动触发 release.yml 演练；7.7 注明体积按现状接受。
- 发布流程与产物沿用现有 `release.yml` / `electron-builder.yml`，没有改动：Windows `DocFlow-4.0.0-win-x64-setup.exe`，macOS arm64/x64 各一份 `.pkg`、`.dmg`、`.zip`，加 `SHA256SUMS.txt`；Release 说明取 `.github/release-notes.md`，里面有带版本号的 macOS 终端命令。

### 怎么验证的

- `npm run check`（本机 Windows）：通过，57 个文件、298 个单测。
- `origin/main` 最新提交 `5bb662a` 的 CI（check、windows/macOS 打包冒烟与 E2E）全绿。
- release.yml 在 4.x 上从未成功跑过（仅有 3 次早期 0 秒失败），Windows NSIS 安装包也从未在 CI 打过；所以先在 `main` 上 `workflow_dispatch` 演练（只打包、上传工件、不发布），通过后在同一提交打 `v4.0.0`。

### 没做成 / 坑

- 跳过的任务与验收：真实论文人工检查（M5-8）、两平台本地打包清单（M6-2）、beta 演练与下载安装验证（M6-3）、M7-1～M7-4 实测；08.6 发布前人工验收清单一项都没有做。
- 安装包体积约 156 MB，超出 130 MB 目标，按现状发布。

### 下一步

- 4.0.x：补做上面跳过的实测（尤其 M5-8 真实论文与 Windows/macOS 实机安装、升级安装）。
