# 2026-09-24 修复 M7-5 核对发现的其余问题

修完 [M7-5 记录](2026-09-24-m7-docs.md) 里剩下的问题（前四条见 [2026-09-24-fixes](2026-09-24-fixes.md)）。

### 做了什么

5 个子代理按文件分工并行修复，每条先复核（能写测试的先写失败测试），全部确认是真问题。

- **PDF 写回**（`pdf/compose/`）：挂公式字体前把页面的 `/Resources`、`/Font` 复制成本页自己的，共用或继承资源时 `DFo<n>` 不再互相覆盖；每页先生成追加指令，成功后才写表单流与页面流，编码失败时整页不动（原来表单里的原文会被删掉而没有译文）；公式重绘后恢复段落颜色；共享表单的子表单（`1/1`）也不改写。
- **共享表单子路径**（`pdf/form-path.ts`，主会话补）：`inSharedForm` 挪到公共模块，analyze 的分行与可翻译判定也按前缀排除，子表单里的文字不再送去翻译。
- **翻译**（`translate/`）：重试用尽抛 `RetriesExhaustedError`，各级阶梯不再接住，文档以可重试失败结束（原来服务长时间不可用会逐段磨完再永久失败）；不可重试的错误不再退避；网络错误、超时、非 JSON 回复给中文提示；HTTP 200 带 error 对象按内容分类，Key 无效不再重试；占位符两侧空格保留；无 Key 的 Anthropic 请求也带 `anthropic-version`；获取模型列表失败抛 `models_failed` 用户错误；最后一次失败不再提示「n 秒后重试」；缓存写入失败记一次处理记录。
- **流水线与 worker**（`pdf/worker-host.ts`、`pipeline/run.ts`、`pdf/verify.ts`）：一个文档取消或超时终止共用线程后，同线程上其他文档的请求在新线程上重发，不再 `worker_crashed`；worker 回传的 stack 写日志；worker 内部异常按永久内部错误处理、界面显示中文通用文案；7 个写回 warning 与校验失败都有中文文案，英文原文进 detail；「第 Q 段」改为本页阅读顺序序号。
- **主进程 / IPC / 界面**：ZIP 导出也记入 `exportedPaths`，「打开所在文件夹」可用；没有窗口时算作后台，完成通知照常发出，点通知在没有窗口时重新建窗口；错误边界的「重新启动」在桥接可用但 `app:info` 无应答时也会出现并真正 `app:relaunch`；0 字节 PDF 在创建时拒绝（「文件是空的（0 字节），请选择其他 PDF。」），删除界面里不会生效的大小检查。
- **打包 / CI / mock**：`electron-builder.yml` 去掉从未被读取的 `pdfjs/{cmaps,standard_fonts}`（约 2.4 MB）；`release.yml` 在分支上手动运行只打包不发布；`ci.yml` 头注释更正；第三方声明不再列出未打包的 `@napi-rs/*` 与未安装的可选包；mock 的 Anthropic 列出的模型可用、Azure 认 `api-key` 头；`compose.test` 用例名与断言一致。
