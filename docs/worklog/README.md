# 工作日志

每个工作会话（一个代理的一次运行，或一个人的一段工作）结束前写一篇，文件名 `YYYY-MM-DD-<slug>.md`，同一天多次会话就在同一文件里追加小节。模板见 [TEMPLATE.md](TEMPLATE.md)。

写日志的目的是让**下一个会话**（很可能是另一个模型、没有任何上下文）能在两分钟内接上：做到了哪一步、怎么验证的、什么没做成、坑在哪。

规则：

- 只追加，不改写、不删除已有内容。
- 写事实：跑了什么命令、结果是什么、改了哪些文件。不写「优化了体验」这类没信息量的话。
- 遇到规划与现实不符，写清楚「规划说 X，实际 Y，我选择了 Z，因为……」，并同步修改规划或写 ADR。
- 未完成的事写进「下一步」，并说明从哪里继续。
