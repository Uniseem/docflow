### 修复前已定的方案（下次照做）

- **列表顺序**：按 `createdAt` 降序、`id` 降序；`store/documents.ts` 导出 `sortDocuments()`，LibraryView 与方向键导航共用。进度更新不能改变行的位置。
- **已完成文档不提供「重新处理」**：以 05 §5.7 为准（只有 failed/cancelled 可以 retry），删掉已完成文档菜单里的这一项，同时改 06 §6.4。
- **新通道 `app:takePendingFiles`**：`{}` → `{ paths: string[] }`。主进程缓存启动参数、open-file、第二实例带来的 PDF，渲染进程订阅 `app:openFiles` 后调用一次取走；之后主进程直接推送。写进 05 章。
- **新通道 `shell:revealExport`**：`{ path }` → `{}`。只允许本次会话 `documents:export` 写出过的路径，其他一律 `not_found`。写进 05 章。
- **导出写入失败**转成带原因的 UserError（没有权限、磁盘满、文件被占用），界面只弹一次。
- **`TranslationPools.invalidate(providerId?)`**：`secrets:set`/`secrets:remove`/`providers:save`/`providers:delete` 后作废该服务商，`changeLibrary` 时全部作废。
- **`ui.openSettings()`**：尚未配置大模型时打开「翻译服务」，否则「通用」；侧栏「设置」和 ⌘, 都用它。
- **调度器关停不算取消**：`stop()` 中断的文档保持 `processing`，下次打开该文档库由 `recoverQueued()` 续跑；只有用户取消才写 `cancelled`。`cancel()` 只对 queued/processing/retrying 生效，且只写一次「已取消处理」。

### 清单

标记：高 / 中 / 低；「可能」表示核实者认为很可能但没完全坐实。

#### 高

1. **文档库打不开会让应用再也起不来**（`main/app/session.ts` changeLibrary、boot；`main/index.ts`）。先写 host.json 再打开新目录，失败不回滚；boot 里 openLibrary 没有兜底，`whenReady` 链没有 catch。选了不可写的文件夹、外接盘拔掉、secrets 解不开，之后每次启动都没有窗口。修法：先在新实例里建目录、试写、加载 settings/secrets/library，全部成功再切换并写 host.json，失败抛 UserError 并保持旧库运行；boot 失败回落到默认文档库并在窗口出现后提示；`whenReady` 加 catch；secrets 解不开当作空并记日志。
2. **代理设置从未生效**（`main/app/session.ts`）。没有任何地方调用 `session.defaultSession.setProxy`（02 §2.5 第 7 步），「自定义」「不使用代理」都无效。修法：`applyProxy()` 按 system/direct/fixed_servers 设置并 `closeAllConnections()`，打开文档库与代理设置变化时调用。
3. **处理记录经常是空的**（`renderer/store/documents.ts`）。只有 `select()` 会拉历史，`list()`/`remove()`/`library:changed` 自动选中的文档不拉；推送事件还会推进游标，之后拉历史只拿到推送之后的。修法：记录已加载的文档，首次加载拉最新 500 条，与推送事件按 seq 合并；DocumentDetail 挂载时触发加载。
4. **「获取模型列表 → 确定」静默失败**（`ProvidersPanel.tsx` PickModelsModal）。已有但远端列表没有的模型被预选，再和手动模型合并后出现重复 id，schema 拒绝，异常没人接，也没有提示。修法：只预选远端列表里有的；确认时去重；savePatch 包 try/catch 并提示。

#### 中

5. **调度器关停把进行中的文档标成已取消**（`main/jobs/scheduler.ts` stop/runOne）。更改文档库、退出应用都会触发，之后不会续跑，和确认框「进行中的任务会在下次打开对应文档库时继续」相矛盾。修法见上面的方案，用独立的 abort reason 区分关停与取消，补单测。
6. **取消已完成的文档**（`scheduler.ts` cancel；`DocumentDetail.tsx`、`LibraryView.tsx` 取消确认）。确认框打开期间文档完成，确认后仍被改成「已取消」，work/ 已删，重新处理要整篇重译；取消进行中的文档还会写两条「已取消处理」。修法：cancel 检查状态；确认框在文档离开进行中状态时自动关闭。
7. **取消/删除可能卡几分钟**（`scheduler.ts` cancel/remove；`translate` 重试等待与并发池排队）。等待不响应 abort，remove 的 5 s 上限被 cancel 的无限等待绕过（05 §5.7 要求最多 5 s）。修法：重试等待与排队可中断；remove/cancel 的等待都用 5 s 上限；中断分支不覆盖更新的状态。
8. **启动参数里的 PDF 丢失**（`main/index.ts`）。Windows 双击 PDF 冷启动时，`app:openFiles` 在页面加载前就发出，渲染进程还没订阅。修法：`app:takePendingFiles`（见方案）。
9. **换文档库后仍用旧 Key 翻译**（`main/translate/pool.ts`）。KeyRing 只建一次，换库、删除服务商后内存里的 Key 不变。修法：`invalidate()`（见方案）。
10. **服务商错误丢了服务端原因**（`main/translate/errors.ts`）。403 一律说「API Key 无效或已欠费」（地区限制、代理问题被掩盖），404 没有原因。04 §4.5 要求「翻译服务返回错误（HTTP n）：<片段>」。修法：只有 401/402 等才说 Key 问题，其他带上片段和下一步建议，同步改 4.5。
11. **计数与搜索结果被推送弄乱**（`store/documents.ts` upsert）。筛选或搜索时，推送的文档不管是否匹配都会加进列表，计数反复累加。修法：把 main 的 matchesFilter/matchesQuery 移到 shared；有筛选或搜索词时改为节流后重新 `list()`。
12. **处理记录重复或丢行**（`store/documents.ts` loadEvents）。请求期间到达的推送事件，增量合并时重复（React key 冲突），首次加载时被整体覆盖掉。修法：按 seq 用 Map 合并，游标只增不减；与第 3 条一起修。
13. **列表行不停跳动**（`App.tsx`、`LibraryView.tsx`）。按 updatedAt 排序，每次进度更新都改 updatedAt，两篇同时处理时来回换位，容易点错；05 §5.4 规定按 createdAt 降序。修法：`sortDocuments()`（见方案）。
14. **全局确认框在执行中可被关掉，且串到下一个确认框**（`components/ConfirmDialog.tsx`）。执行中按 Esc 关掉后，下一个确认框按钮一直转圈，之后又被上一个操作自动关闭。修法：执行中禁止关闭；只清除自己那个 confirm；按 confirm 对象加 key。
15. **导出成功提示打开的是文档库副本**（`DocumentDetail.tsx`）。「打开所在文件夹」定位到 `documents/<id>/output/`，文件名也是建议名而不是实际保存名。修法：`shell:revealExport` 与 `basename(result.path)`（见方案）。
16. **已完成文档的「重新处理」永远失败且没有提示**（`DocumentDetail.tsx`）。修法：按方案删除该菜单项，改 06 §6.4。
17. **阶段显示落后一个阶段**（`DocumentDetail.tsx` StageIcon、列表行阶段名）。流水线只在阶段结束时写 stage/progress，Key 错误的失败图标会标在「分析版面」上。修法：每个阶段开始时写一次 `{stage, progress: from}`（只改 manifest，不记事件）。
18. **「文档信息」抽屉出现在左边**（`DocumentDetail.tsx` InfoDrawer）。宽度写在 `Drawer.Content`（定位层）上，与窄窗口详情抽屉修过的是同一个错误。修法：宽度放到 `Drawer.Dialog`。
19. **超过 200 篇时虚拟列表算错**（`LibraryView.tsx`）。按 88 px 计算，实际行高约 53/73 px，底部留白、方向键选到未渲染的行。修法：固定行高或实测首行高度；键盘选中时直接设置 scrollTop。
20. **自定义「附加请求参数」清不掉**（`ProvidersPanel.tsx` savePatch）。清空后按「应用」，旧 JSON 又被存回去。修法：用 `'extraBody' in patch` 判断。
21. **一个无效输入让之后所有保存都静默失败**（`ProvidersPanel.tsx`、CustomProviderModal）。渲染进程里 parse 抛错没人接，而且每次保存都带上无效草稿。修法：失焦时 safeParse 并显示字段错误，其他控件的补丁用已保存的值，外层 try/catch 并提示。
22. **没有协议头的地址报「内部错误」**（`shared/types.ts`）。refine 里的 `new URL()` 在 zod 4.6 会抛 TypeError，`127.0.0.1:7890` 这类输入变成内部错误和两条 Toast。修法：改用 `z.url({ protocol: … })` 或 `URL.canParse`；网络页「应用」前先校验，空值时禁用。
23. **单个文件时标题永远是文件名**（`NewTranslationModal.tsx`）。预填的文件名总被当作自定义标题发出，PDF 元数据标题永远不会替换它（05 §5.7）；增删文件后预填值也不更新。修法：用户没改过就不发 title。
24. **cancel-retry.spec 的同步点无效**（`tests/e2e/cancel-retry.spec.ts`）。`/…|翻译/` 命中常驻的「新建翻译」按钮，取消落在哪个阶段全凭运气。修法：用 `documents:get` 轮询到 translate 阶段再取消；给 mock 加延迟选项。
25. **mock 服务全程不重置，每第 9 个请求返回 429**（`tests/e2e/global-setup.ts`）。first-run 的「检查」可能正好撞上，结果取决于前面测试发了多少请求。修法：每个测试开始时 `POST /reset`，或让周期 429 只对特定 Key 生效。
