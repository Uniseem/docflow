# 2026-09-26 PDF 处理照搬 PDFMathTranslate 1.9.11

## 会话 1（Claude Code / Opus 5.5，Windows 机器，9 月 25 日晚至 26 日）

### 目标

维护者用 4.0.0 翻译一篇 61 页的 ChemistrySelect 综述，中文 PDF 里很多段落的英文原文没删掉，译文叠在原文上。维护者要求：不要自己设计，照抄 PDFMathTranslate（pdf2zh）的逻辑。对应 M8（09 章），决定见 ADR-0016。

### 做了什么

- **原因**：4.0.0 用几何规则分段，只删「起点落在段落框里」的文字算子（ADR-0008、ADR-0015）。维护者那篇论文第 2 页上半部分的段落，英文算子没有被选进删除集合。
- **维护者的三个决定**：
  - 模型与字体打进安装包（不像 pdf2zh 那样首次使用时下载）；
  - 翻译请求也照抄（一段一请求、pdf2zh 提示词），服务商、Key、重试、缓存、并发沿用 DocFlow 的实现；
  - 页面渲染用 MuPDF.js，接受它的 AGPL-3.0，而不是只用 MIT 的 pdf.js。
- **参考环境**（开发机临时目录，不在仓库）：Python 3.13 虚拟环境装 `pdf2zh==1.9.11`（`--ignore-requires-python`，`tencentcloud-sdk-python-tmt==3.0.1478`），假翻译器替换 `GoogleTranslator`，`sys.settrace` 取 `receive_layout` 的局部变量，包装 `OnnxModel.predict` 导出输入图与框。维护者论文 61 页 50 s，17 个样例都跑通（`empty`、`encrypted` 被 pdf2zh 拒绝）。导出 `tests/fixtures/pdf2zh/*.json`。
- **移植**（`src/main/pdf/pdf2zh/`）：
  - `parse.ts`：`receive_layout` A 部分；
  - `typeset.ts`：C 部分；
  - `interp.ts`、`pages.ts`：`pdfinterp.execute`、`do_S`、`do_Do`，以及裁剪框与旋转；
  - `doclayout.ts`：模型前后处理与版面矩阵；
  - `render.ts`、`detect.ts`：MuPDF.js 渲染，onnxruntime-web 推理；
  - `chars.ts`：pdf.js 字形换算成 `LTChar`，并与原始算子对齐；
  - `unicode.ts`：pdfminer `to_unichr`，数据表 `pdfminer-tables.ts` 由 pdfminer 生成；
  - `segments.ts`：待翻译段落。
  - 分析与写回入口（`pdf/analyze.ts`、`pdf/compose/index.ts`）改写。旧的 `analyze/lines|columns|formula|paragraphs|normalize`、`compose/content-walker|emit|fonts|layout|rewrite|resources`、`pdf/forms.ts`、`form-path.ts` 删除。
- **流水线**：分析阶段先逐页版面检测（worker `detect` 请求，检查点 `work/layout.json`，事件 `版面检测 i / N 页`），再分析。检查点读回时做 zod 校验。`writtenPages` 只记写入了译文的页。
- **翻译**：`translate-document.ts` 改为逐段请求，`pdf2zh-prompt.ts` 放提示词、`safe_substitute` 与回复清理。`batch/protect/validate` 删除；缓存不再校验；空 system 不发。拒绝回答时保留原文。4.0.0 的默认提示词在读设置时迁移。设置页去掉批量参数与「译文最小缩放」。
- **资源与打包**：思源宋体 `SourceHanSerifCN-Regular.ttf` 替换 Noto（提交进 git）。`scripts/fetch-model.mjs` 下载模型并校验 SHA3-256，`predev`、`prebuild` 自动运行，另有 `npm run model`。electron-builder 只带 onnxruntime-web 的三个文件，把 ort 与 mupdf 解包出 asar。CI 与发布流程加模型缓存。第三方声明与 README「许可」写明 AGPL。
- **测试**：`analyze.test.ts` 改为与 pdf2zh 逐页比对；新增 parse、typeset、interp、doclayout（含一次真实检测）、unicode、chars、pdf2zh-prompt 单测；compose、verify、pipeline、translate、smoke 按新行为改写。smoke 用真实模型在进程内跑。
- **文档**：ADR-0016（0008、0015 标为废弃，0003 标为部分修订）。03 章整章重写；02、04、05、06、07、08 章相应段落改写。README（介绍、已知问题、许可）、CHANGELOG、pdfmathtranslate-notes、09 章 M8 都已更新。

### 怎么验证的

- `npm run check`：55 个测试文件、338 个用例，全部通过，本机约 40 s。
- **分段一致**：给定 pdf2zh 的框，14 个样例和维护者论文 61 页的 `sstk` 与 pdf2zh 逐页相同，公式组 28170 个也相同。
- **写回一致**：维护者论文写回后，61 页提取文字与 pdf2zh 输出逐字相同，54309 个单词位置最大差 0.016 pt。
- **模型**：用 pdf2zh 实际喂给模型的图跑我们的预处理和推理，35 个框逐个相同。用 MuPDF.js 渲染，52/61 页的框与 pdf2zh 在容差内一致，最终分段 60/61 页相同（第 54 页多一个框）。
- **应用内**：`dist:dir` 后 E2E 8 个全部通过（隐藏窗口）。开发构建用假服务商跑维护者论文：61 页约 2 分钟完成，版面检测约 85 s，校验通过。

### 没做成 / 坑

- **pdf.js 渲染行不通**：最初用隐藏窗口里的 pdf.js 渲染页面给模型，61 页中 8 页多出低置信度的整栏框，参考文献页每栏被并成一段。这一版做完后撤掉了（隐藏窗口、preload、`docflow://pdfjs` 路由都已删除），改用 MuPDF.js 在 worker 里渲染。
- **pdfminer 的 `"` 缺陷不照搬**：`do__w` 少了 `T*`，`tj-arrays` 样例分段因此不同。
- **坐标精度**：pdf.js 算子流的矩阵是 float32，坐标约差 1e-5。
- **写测试时预期写错过几次**：括号规则、首字母放大、无 `brk` 时切段、行高浮点循环停在 0.9999999999999996。每次都对照 pdf2zh 源码或 Python 实算后改测试，没有改实现。
- **Python heredoc 的转义**：用 Python 改 TypeScript 源码时，`\n`、`\b` 被转义成真实字符，出过几次语法错误；后来改用写脚本文件或 Edit 工具。
- **pdf2zh 自身的问题一并带来了**（README 已知问题）。维护者这篇论文的空格是 6.4 pt 的 `dummy-space` 字体，被角标规则判成公式，译文词间会有空隙，pdf2zh 也一样。
