# 2026-09-23 M5 界面修复与 E2E 跑通

## 会话 1（Claude Code / Opus 5.5，12:15）

M5-7：让 08.5 七个 E2E 全绿。接手 [2026-09-22 的 M5 记录](2026-09-22-m5-ui.md)：界面代码已写好但从未真正跑起来过，E2E 只有 `window-title` 能过。

### 做了什么

- **撤销内联经典脚本方案**（ADR-0009 已改写）。`scripts/inline-renderer.mjs` 用 `String.replace` 的字符串参数内联 bundle，bundle 里的 `$$`、`` $` ``、`$&` 被当成替换模式，把 HTML 头拼进 JS，窗口显示一堆源码（用户看到的「乱码」）。复查发现 asar 里的 `<script type="module">` 本来就能执行，上次的「module 不执行」是误判。已删除内联脚本、`asarUnpack`、`dfapp://` 协议、`stripCrossorigin`；CSP 回到 `script-src 'self'`。保留 preload 打包 zod。
- **界面空白的真正原因**，逐个修掉：
  1. `App.tsx` 把整个界面包在 `<Toast.Provider>` 里。HeroUI 3 的 `Toast.Provider` 是 toast 区域，`children` 是每条 toast 的渲染模板，没有 toast 时什么都不渲染。改为根部独立的 `<Toast.Provider placement="bottom end" />`。
  2. `<Tabs.Indicator />` 放在 `Tabs.List` 里与 `Tabs.Tab` 并列，React Aria 抛 `<SharedElement> must be rendered inside a <SharedElementTransition>`，整棵树被卸载。文档详情、设置两处都改成每个 `Tabs.Tab` 内各放一个。
  3. `DocumentDetail` 的 zustand selector 每次返回新数组（`?? []`），React 无限重渲染后崩溃。
  4. 没有错误边界：任何渲染错误都让窗口整块变白。`main.tsx` 加了错误边界。
- **HeroUI 用法审计**：6 个子代理按文件分工，对照 `.heroui-docs` 与类型定义逐个核对组件，约 40 处修正。主要有：Radio/Switch 的 `Control` 放在 `Content` 外（点不到）；`Dropdown.Trigger` 里再套 `Button`（按钮嵌按钮）；窄窗口 Drawer 宽度写在定位层上、关闭后被自动选中重新弹开；全局快捷键在对话框/输入框里也触发 Delete 与方向键；确认框改用 `AlertDialog` 并处理异步失败；Slider 拖动时每一步都发 IPC；`border-divider` 不是 HeroUI 3 的颜色令牌。
- **IPC 错误丢失 `code`/`user`**：contextBridge 复制 `Error` 时只保留 `message`，所有用户错误在界面上都变成「发生内部错误」。preload 改为以普通对象 `IpcFailure` reject，`renderer/api/errors.ts` 的 `toDocflowError` 还原成 Error（新增单测）。规划 05 章已补充说明。
- **E2E 改写了真实用户目录**：`DOCFLOW_DATA_DIR` 只覆盖文档库，`host.json`、Chromium 缓存与单实例锁仍在真实的 `~/Library/Application Support/DocFlow`。`settings.spec` 的「更改文档库」把真实 `host.json` 改成指向临时目录、主题改成深色。现在有 `DOCFLOW_DATA_DIR` 时主进程把 `userData` 设到 `<dir>/.electron-user-data`；真实 `host.json` 已恢复为 `{}`（该目录里没有 4.x 文档）。
- **spec 修正**（没有放宽断言内容）：`/处理中|…|翻译/`、`/缓存/`、`/已加密/`、`/API Key/`、`/模型/`、`校验通过` 按设计会同时出现在状态标签、进度行、处理记录里，Playwright 严格模式下必须 `.first()`；`failure.spec` 把 `settings:get` 返回的视图对象（带 `keyConfigured` 等只读字段）原样传给 `providers:save`，被严格 schema 拒绝，改为只传配置字段；`settings.spec` 的原文档库目录改名为 `DocFlow`，因为 `library:change` 会给非 `DocFlow` 目录追加 `/DocFlow`（05 章），原来「改回原位置」其实进了空的子目录。

### 没做成 / 坑

- **界面空白先查 React 是否渲染了内容**：`#root` 有 `__reactContainer$…` 键但为空，说明挂上了但渲染出空树或已卸载。Playwright 的 `pageerror` 监听要在触发崩溃的操作之前挂上；启动时的错误可以在页面里 `import(脚本URL + '?again')` 重新执行来复现。Electron 的 Playwright trace 不含页面错误，error-context 也没有页面快照。
- **HeroUI 3 的 Provider/Indicator 类组件**必须看 `.heroui-docs` 的 Anatomy。`switch.mdx` 的 Anatomy 块与实现矛盾（示例与实现都把 Control 放在 Content 里），以实现为准。
- **zustand 5 selector 不能每次返回新引用**（`?? []`、`.filter()`），否则无限渲染。
- **打包产物带了原生模块**：pdfjs-dist 的可选依赖 `@napi-rs/canvas` 被打进 `app.asar.unpacked`（含 `.node`），违反「不引入原生模块」。M6 打包时在 electron-builder `files` 里排除并确认解析/写回不受影响。
- `restart.spec` 用 mock 服务时 `long.pdf` 很快，关窗前可能已进入翻译阶段甚至接近完成，断点续传覆盖得不深。
- 审计子代理记录但未改的问题：多处 `void invoke(...)` 在用户错误时没有提示（未处理的 rejection）；重命名框没有全选；文档 store 在 `list()`/`upsert()` 时自动选中第一项；新建翻译弹窗添加时只能校验扩展名（沙箱里拿不到文件大小）；`LibraryView` 等处仍有 `border-divider`（无效类名，视觉无影响）。
