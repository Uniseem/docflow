# 01 目标与范围

## 1.1 产品定义

DocFlow 4.0 是一个离线优先的桌面应用：**输入带文本层的 PDF（主要是英文学术论文），输出保留原版式的简体中文 PDF 和「原页 / 译页」交替的双语对照 PDF。** 翻译由用户自己配置的大模型 API 完成；应用本身不提供任何云服务，不上传文件到 DocFlow 的服务器（根本没有服务器）。

用户画像：中文研究者/学生，会自己申请 DeepSeek 等服务的 API Key，一次翻译几篇到几十篇论文，希望「拖进去、等一会、拿到能读的 PDF」。

## 1.2 必须做到（4.0.0）

## 1.3 明确不做（4.0.0）

- OCR / 扫描件、加密 PDF、竖排文字、非左到右书写系统的 PDF。
- 版面检测模型（DocLayout-YOLO 等）、任何原生模块。
- Markdown 阅读视图、期刊风格重排 PDF、Typst、KaTeX。
- 术语表 / 词汇表、多语言目标（只出简体中文；`targetLanguage` 字段预留但界面不暴露）。
- 自动更新（只做「检查更新」链接）。
- 云同步、多设备、账号。
- 翻译质量分档（3.x 的 tier 已废弃）。
- 界面多语言（界面只有简体中文）。

## 1.4 成功标准

见 [README.md](README.md) 的「完成的定义」。补充量化指标（在开发机 Apple M 系列 / 8 核 x64 上）：

- 30 页两栏论文，解析 + 段落合并 ≤ 5 s；写回 + 双语 + 校验 ≤ 15 s；总时间由大模型速度决定。
- 应用冷启动到文档库可交互 ≤ 2 s；主进程常驻内存 ≤ 300 MB（不含正在处理的文档）。
- 安装包：Windows ≤ 130 MB，macOS 每架构 ≤ 130 MB。

## 1.5 术语

| 术语                    | 含义                                                                                |
| ----------------------- | ----------------------------------------------------------------------------------- |
| 文档（document）        | 用户加入的一份 PDF 及其全部产物，`documents/<id>/`                                  |
| 文档库（library）       | 存放所有文档、设置、密钥、日志的目录                                                |
| 任务（job）             | 一次对文档的处理尝试；一个文档同一时刻最多一个任务                                  |
| 阶段（stage）           | 任务内的步骤：received / inspect / analyze / translate / compose / verify / archive |
| 段落（paragraph）       | 解析出来的可翻译单元，含位置、字号、文本（带占位符）                                |
| 片段（segment）         | 送去翻译的文本单元，与段落一一对应（超长段落拆分时才多于一）                        |
| 占位符（placeholder）   | 段落文本里代表公式等不可翻译对象的 `{v1}`；送模型前再换成 `DOCFLOWKEEP000001TOKEN`  |
| 译页（translated page） | 覆盖并写入译文后的页面；双语 PDF = 原页、译页交替                                   |
| 服务商（provider）      | 一个大模型 API 端点的配置（类型、地址、Key、模型列表、并发）                        |
| 翻译器（translator）    | 一次任务选定的「服务商 + 模型」                                                     |
