# ADR-0006：行内公式等不可翻译对象用栅格化贴图保留位置

- 状态：**已废弃**（同日被 [ADR-0008](0008-content-stream-rewrite.md) 取代：公式改为用原字体资源与原编码矢量重绘，不再栅格化，也不再需要隐藏窗口）
- 日期：2026-09-21
- 相关：docs/plan/03-pdf-pipeline.md（旧版 §3.6，已删除）

## 背景

段落里夹着的行内公式（`$x_i^2$`）、特殊符号、上下标，翻译后会随译文一起重新排版，位置必然变化。BabelDOC 的做法是保留原字形并按新位置重画，这需要把原 PDF 的字体资源和文字绘制指令搬到新位置——在 pdf-lib 里没有现成 API，要自己解析内容流，风险高。

## 决定

- 解析阶段把公式片段替换为占位符 `{v1}`、`{v2}`……并记录每个片段在原页上的包围盒。
- 在一个**隐藏的 BrowserWindow**（`src/raster/`，加载 pdf.js 的 web 版）里把原页按 4× 缩放（288 dpi）渲染到 canvas，按包围盒裁出 PNG（透明背景不可行，pdf.js 渲染的是白底；裁图时取包围盒外扩 1 pt）。
- 写回阶段把译文排版好之后，占位符所在位置按原片段的宽高（乘以字号缩放比）留出空位，用 `drawImage` 把 PNG 贴上去。
- 整行/整块的独立公式（display math）不翻译、不覆盖、不贴图，原样保留。
- 图片、表格线、图表等非文本对象从不覆盖。

## 备选方案

- 解析并搬运原始内容流（BabelDOC 做法）：最忠实，但实现量与风险都大，留作将来。
- 用 Unicode 文本重画公式：pdf.js 提取的公式文本常常缺 ToUnicode 映射或丢失上下标位置，结果不可读。放弃。
- 主进程用 `@napi-rs/canvas` 栅格化：原生模块，且跨架构打包（在 arm64 上打 x64 包）时可选依赖装不上。放弃。

## 后果

- 好处：所见即所得，任何字体与编码都能正确保留；纯 JS。
- 代价：公式变位图，放大到 300% 以上会有锯齿；每张贴图 5–50 KB，公式密集的论文输出会大几 MB；栅格化需要一个隐藏窗口，主进程要管理它的生命周期。
- 跟进：给「公式贴图缩放倍数」留一个高级设置（默认 4，范围 2–8）。
