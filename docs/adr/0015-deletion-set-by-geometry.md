# ADR-0015：写回的删除集合按几何位置与数量确定，不按算子序号逐个匹配

- 状态：已采纳（修订 ADR-0008 的删除判定）
- 日期：2026-09-22
- 相关：M3-5、M3-7、docs/plan/03-pdf-pipeline.md（3.12.3）、worklog 2026-09-22-m3-compose

## 背景

ADR-0008 定下「只删除被翻译段落的 show-text 算子」。规划 3.12.3 原设计：分析侧（pdf.js 算子流）给每个字形记录算子序号 `opSeq`，改写侧（自写的内容流遍历器）按同样顺序给算子编号；两边数量不等时，按每个 `opSeq` 首字形坐标逐个匹配找出差异。

M3 用真实论文实测：遍历器与 pdf.js 在复杂页（表单嵌套、`TJ` 拆分、标记内容）上的算子计数仍会差几个，逐个匹配经常找不齐，差异超过阈值的页只能整页放弃改写。

## 决定

- 期望数量 `expected` = 被翻译段落各行 `opSeqs` 的并集大小（`opSeq` 只用来计数）。
- 删除集合（`compose/rewrite.ts` 的 `deletionSet`）只看算子起点的几何位置，依次放宽直到数量不少于 `expected`：行框（外扩 `REMOVE_PADDING`）→ 段落框 → 段落框外扩 3 倍内的其余算子按到各行基线的竖直距离由近到远补足；多于 `expected` 时只留离基线最近的 `expected` 个。
- 一致性校验保留：最终数量 ≠ `expected` 记 warning `op_mismatch`；差异超过 `PAGE_SKIP_MISMATCH_RATIO`（10%）整页放弃（`page_skipped`）。

## 备选方案

- **按 `opSeq` 严格对应**：要求两套状态机对每种算子的计数完全一致，真实论文里做不到，整页放弃太多。放弃。
- **只按段落框删、不看数量**：会误删框内不属于段落的文字（图内标签、相邻脚注）且没有任何校验。放弃。

## 后果

- 好处：两篇真实论文 `page_skipped = 0`；LLaMA 只剩 2 条 `op_mismatch`（差 2–4 个算子，低于阈值）。
- 代价 / 风险：一致性校验变弱——数量对得上不代表删的是同一批算子。段落框附近恰好有同样多的不相关文字时可能误删一个、漏删一个，校验发现不了；表现为某行原文残留或相邻一小段文字消失。
- 需要跟进的事：M5-8 真实译文检查时留意原文残留与缺字；有样例就加进 fixtures。
