# ADR-0008：写回采用内容流改写（PDFMathTranslate 方式），公式用原字体重绘

- 状态：已采纳（取代 ADR-0006；删除集合的判定由 ADR-0015 修订）
- 日期：2026-09-21
- 相关：docs/plan/03-pdf-pipeline.md §3.12、docs/reference/pdfmathtranslate-notes.md

## 背景

ADR-0003 最初设想的写回是「白色矩形覆盖原段落 + 用 pdf-lib 画译文 + 行内公式栅格化贴图（ADR-0006）」。维护者要求处理逻辑参照 [PDFMathTranslate](https://github.com/PDFMathTranslate/PDFMathTranslate)。它的做法是：解释内容流得到每个字符的位置、字体资源名与字符编码；重建一份**去掉全部文字指令**的图形指令流；再把译文与搬动位置后的公式字符（用原字体资源名 + 原编码）追加回去。好处是没有白块、公式保持矢量与原字体、图表文字原样保留。

## 决定

- 解析用 pdf.js 的算子流（`getOperatorList`）自己解释文字状态，得到逐字形记录（编码、`loadedName`、渲染矩阵、颜色、算子序号）。
- 写回用自写的内容流词法分析器 + 定位遍历器，**只删除**被翻译段落的 show-text 算子（按算子起点落在段落框内判定），其余字节原样保留；不重新序列化任何未删除的 token。
- 译文用嵌入的 Noto Sans SC 追加到页面级内容流末尾；`{vN}` 公式片段按原相对位置、原字体资源（通过起点匹配把 pdf.js 的 `loadedName` 映射回资源名，失败再按 BaseFont 匹配）、原编码逐字形重绘，保留颜色。
- 单页独占的 Form XObject 递归处理；被多页共享的表单不动。
- 不再需要隐藏栅格化窗口；ADR-0006 废弃。

## 备选方案

- 覆盖 + 栅格化（ADR-0006）：实现简单，但白块与位图公式的观感差，且不符合维护者要求。废弃。
- 完全照搬 pdf2zh「删除全部文字、保留区域原位重绘」：需要为每个不翻译的字形重新编码与定位，风险面更大；只删被翻译段落的指令效果等价且更安全。
- 用 MuPDF.js 的 redaction 删除文字：AGPL，且仍要自己重绘公式。

## 后果

- 好处：输出质量接近 pdf2zh；纯 JS；不动的内容零风险。
- 代价：要写内容流词法分析器与两套文字状态机（pdf.js 算子流侧、原始流侧），并保证两者坐标一致（有一致性校验与整页放弃机制）；分式横线等路径元素暂不随公式搬动。
- 跟进：M2/M3 用真实论文验证映射成功率；收集 `op_mismatch`、`font_unmapped` 的样例到 fixtures。
